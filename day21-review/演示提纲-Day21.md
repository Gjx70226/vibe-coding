# Day 21｜第三周验收演示提纲（3–5 分钟）

> 用途：对着这份提纲完整走一遍，证明「数据是真的、链路是通的」。计时从「打开链接」起到「刷新后读到刚写的那笔」止，5 分钟内走完核心流程 = 合格。

## 1. 用户问题（为什么做这个）
怎么确认我做的四级备考网站「数据是真的、链路是通的」？
——别人打开公网链接，看到的是云里**真实数据**，不是我提前写死在页面里的假数据；而且写入的东西刷新后还在。

## 2. 核心流程（含一次真实写入 + 刷新持久化）
1. **打开公网链接**：`https://cet4-word-helper.app.workbuddy.host/api.html`
2. **取今日计划**：点一下，云回 `ok:true` + 真计划（日期、目标数、真单词）——证明「读的是真库」。
3. **记一笔（真实写入）**：填一个测试词，点「记一笔」，云回 `insert`、行数 +1。
4. **刷新页面**：浏览器刷新（模拟用户关掉重开）。
5. **再取记录**：刷新后重新取记录，看到刚才那笔**还在**——证明「写入持久化了，不是临时显示」。
6. 收尾清掉测试笔（不污染云）。

## 3. 提示词改写过程（这周怎么把话说明白的）
- 一开始只会说「做个热搜页面」→ 含糊，AI 容易给你假数据糊弄。
- 改成：「按 `api-contract.md` 调**公网接口**，跨域只放行我自己域名、禁用 `*`；**本地先调通**（看到真数据）再发版」。
- 结果：AI 把页面从 mock 切成真接口，公网同源天然不跨域，F12 里请求全是公网地址、无 `localhost`、无红字。

## 4. 验证方式（怎么验真假）
- **真数据**：在云里改一条（如目标 20→7），刷新页面跟着变 = 连的是真库；不变 = 还在用 mock。
- **真链路**：F12 → Network，请求地址是 `https://...` 公网、不是 `localhost`；没有 `Access-Control-Allow-Origin` 红字。
- **真写入**：上面第 3–5 步，写一笔刷新还在。

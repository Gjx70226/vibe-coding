# Day 24｜Bug 修复记录：长按题干看释义「一抖就取消」

## 【现象】
手机和电脑上长按答题题干（英文单词），下面的提示条永远是「长按题干，看另一半意思」，中文释义不出现——功能像没有。（小甘 2026-10-03 真机报告 + Day 24 再次确认）

## 【复现步骤】
1. 打开网站 → 新词学习（或错题复习/每日复习）
2. 手指/鼠标按住题干单词 ≥0.5 秒
3. 观察题干下方的提示条
预期：出现「单词 /音标/ ＝ 中文意思」；实际：一直不变。

可复现性说明（诚实记录）：桌面**稳稳按住不动**时功能是能出来的（复现脚本 A 场景触发成功，截图为证）；失败发生在「按住期间有微小移动」时——真实手机手指按下必然微抖，电脑按住稍一滑出题干区域也是常态。无头浏览器无法真实模拟系统手势取消，所以用「代码证据链 + 真实浏览器事件标准」定位，最终以小甘真机验证为准。

## 【定位：怎么排除其他原因、锁定真因】
排除项（都有证据，不是猜）：
1. ❌「功能没写」——quiz.js 249–260 行绑定了按下/松开事件；复现脚本稳按 0.7s，提示条成功变成「manage /ˈmænɪdʒ/ ＝ 管理；设法」（修复前截图）。
2. ❌「样式缺失看不见」——style.css 607 行 `.peek-tip.open` 有完整蓝框样式，截图可见。
3. ❌「当前词为空导致跳过」——render 时 current 正常赋值（269 行），释义有值。

真因（第 254–255 行，代码事实）：
- `touchstart` 用了 `{passive:true}`——「只听不拦」，系统长按菜单/选词照样弹；
- 把 `touchmove、mouseleave、scroll` 全绑成「立即取消计时器」——真实手指按下必微抖（touchmove 必发）、鼠标按住稍一滑出元素（mouseleave 必发），0.5 秒计时器当场被清，长按永远出不来。
- CSS 缺 `touch-action:none` 和 `-webkit-touch-callout:none`，手势和系统菜单没被真正拦住。

这一条根因同时解释了「手机必失败」（微抖必发）和「电脑有时失败」（滑出元素/没按够 0.5 秒）。

## 【修复】
- quiz.js：改用 pointer 事件（按下启动 / 松手或系统取消才停止），pointerdown 时 preventDefault 拦系统默认；删掉「移动即取消」三条误伤源。
- style.css：`.word-display` 补 `touch-action:none`（防滚动打断）、`user-select:none`（防选中文字）、`-webkit-touch-callout:none`（防系统菜单）。
- index.html：quiz.js / style.css 版本号升到 `20261010b` 防缓存。

# Day 26｜回滚手册（同一链接重发，网址不变）

适用场景：发完 v1.0 后发现不对，要退回到上一版（db9b6a9 / 2026-10-10b）。

## 前提（现在已经具备）
- 已在 v1.0 对应代码上打标签 `v1.0`（commit 2708d07）
- 上一版代码标记：`db9b6a9`（内部版本号 2026-10-10b）
- 线上是静态站，重发就覆盖，网址不变

## 回滚步骤（照抄即可）
1. 记开始时间：
   `T0=$(date +%s)`
2. 把电脑里的文件换成旧版（此时文件夹会变「脏」，这是正常的，不是坏了）：
   `git -C "E:/work Buddy运行/微信/vibe-coding" checkout db9b6a9 -- .`
3. 用发布工具重新发一次这个目录（覆盖，网址不变）
4. 确认线上变旧版：
   `curl -s https://cet4-word-helper.app.workbuddy.host/ | grep 'components.js?v='`
   应看到 `2026-10-10b`
5. 记结束时间，算耗时：
   `T1=$(date +%s); echo "回滚耗时=$((T1-T0)) 秒"`

## 恢复步骤（从旧版回到 v1.0）
1. 记开始时间：
   `T2=$(date +%s)`
2. 把电脑里的文件换回 v1.0（文件夹恢复干净）：
   `git -C "E:/work Buddy运行/微信/vibe-coding" checkout HEAD -- .`
3. 用发布工具再发一次这个目录（覆盖）
4. 确认线上回新版：
   `curl -s https://cet4-word-helper.app.workbuddy.host/ | grep 'components.js?v='`
   应看到 `20261011e`
5. 记结束时间，算耗时：
   `T3=$(date +%s); echo "恢复耗时=$((T3-T2)) 秒"`

## 实测数据（2026-10-13 演练）
- 回滚耗时：**40 秒**
- 恢复耗时：**45 秒**
- 结论：一分钟内能完成退版 / 恢复，线上网址始终不变

## 云函数 / 数据库恢复说明（当前不用，先留着）
本项目是纯前端，学习进度存在**你自己的浏览器里**，没有后端、没有数据库。
所以「回滚」只是退代码，不会动到任何人的学习记录，各人各存各的。

以后如果接了云函数 + 数据库，回滚还要额外注意：
- 云函数：发布平台一般能按版本退回，退代码就行
- 数据库：**别跟着退**。用户数据各自独立，回滚代码不碰数据
- 兼容性坑：旧版代码要能读新版写进去的数据，不然回滚后页面报错。这点接后端时要专门测
- 具体操作等接后端时再补进本手册，本次只做了代码层回滚演练

## 注意事项
- 演练中间文件夹会短暂变「脏」（被换成旧版文件），恢复步骤会还原，别在脏的状态提交
- 每次退版 / 恢复后，都用上面的 curl 看线上版本号，确认真的变了，别凭感觉
- 手机端：让小甘在 vivo 真机点一遍长按（电脑/无头验证不能代替真机）

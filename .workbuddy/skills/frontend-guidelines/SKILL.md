# 前端页面设计审查与修复（项目内版）

> 给「四级备考助手」项目定的视觉检查清单。**每次改页面外观，照三步走**：
> **改前查什么 → 改时守什么 → 改完怎么验**。

## 文件位置
- 本文件：`项目根目录/.workbuddy/skills/frontend-guidelines/SKILL.md`
- 同源人读版：`项目根目录/design-rules.md`
- 调用记录与证据截图统一放：`项目根目录/dayXX-review/`（XX 为当日天数）

## 调用方法
- 对话里说「设计审查 / 美化页面 / 审查本页 / 改样式 / 前端审查 / UI 审查」触发（匹配上面的触发词）；或在 Skill 工具里选 `frontend-guidelines`。
- 调用后严格按下面「一、改前审查 → 二、改时遵守 → 三、改完验证」三步执行，并产出 before/after 截图 + `dayXX-review/SKILL_CALL.md` 调用记录。

## 适用场景
- 用户要求"美化 / 审查 / 改样式"任意前端页面（HTML/CSS）
- 用户交来一份"设计规则 / Skill"要求照着查
- 用户要验收页面在对比度、间距、对齐、手机宽度上的表现

## 一、改前审查（6 个维度，逐页过）

| 维度 | 检查什么 | 不合格的信号 |
|------|----------|------------|
| 颜色对比 | 彩色字压在白/浅底上够不够深 | 发灰、发飘、像没加载完 |
| 字体大小 | 主标题/正文/辅助字分层 | 正文小于 13px、主次不分 |
| 信息层级 | 标题→卡片→说明从大到小 | 一眼看不出重点 |
| 间距 | 卡片内、元素之间留白统一 | 挤在一起，或忽大忽小 |
| 按钮状态 | 默认/悬停/激活/禁用齐全 | 点了没反馈 |
| 移动端 | ≤560px 单列布局 | 横向滚动、文字被挤掉 |

**做法**：先只读不改，把问题列成清单（最多 5 个，不足如实说明），并截**修改前**截图存 `dayXX-review/before_*.png`。

## 二、改时遵守（边界，不许越过）

- 只修毛病，不加新装饰（渐变、光效、新组件）
- 不改页面结构、不新增页面
- **不动 JS 逻辑**——美化不能让按钮点不动、跳转失效
- 颜色统一走 `style.css` 顶部 `:root` 变量，禁止在页面里写死色值

## 三、改完验证（四步）

1. 刷新页面，肉眼看修复位置
2. 窗口拉到 ≤560px 宽，复查文字、按钮、卡片
3. 点一遍按钮/链接，确认功能没坏
4. 截**修改后**截图 `dayXX-review/after_*.png`（同位置对比）

## 四、配色标准（已验证对比度达标，白底）

| 变量 | 值 | 用途 |
|------|-----|------|
| `--accent-blue` | `#2563eb` | 入口蓝、激活按钮 |
| `--accent-red` | `#d6453a` | 强调红、错误提示、待复习标 |
| `--accent-green` | `#1e9e57` | 在线绿、已掌握标 |
| `--text` | `#222222` | 主文字 |
| `--text-soft` | `#666666` | 次要文字 |

新增彩色文字时，先查上表有没有对应变量；没有就**先加变量再用**，别写死色值。

## 五、工作流（一次修一个，方便回退）

1. 只审查 → 出 before 截图
2. 一次修一个问题（改对应文件，说明改了哪个文件 + 怎么验证）
3. 修完刷新/截图确认
4. 手机宽度复查
5. 全部修完 → 列改动文件清单（注明各属哪天任务）→ 提交推送 → 停下等确认

## 六、完成标准（交付前自查）

- ≥3 处可指出的改善
- 文字和按钮没有溢出（手机宽度复查过）
- 交互没有因为美化而失效
- 每处改善都有修改前/后证据

## 七、3 个可观察的成功标准（调用后据此验收）

1. **证据成对**：`dayXX-review/` 下存在修改前 `before_*.png` 与修改后 `after_*.png`，且 after 图带页面内地址栏、能看清本次新增/改动的交互控件。
2. **问题可指**：本次调用在 `SKILL_CALL.md` 里至少列出 ≥3 处「与设计规则不符」的发现（或写明 0 处并说明已符合），每条对应 before/after 证据。
3. **不破坏功能**：在 ≤560px 宽度复查无横向溢出，且原有按钮/链接功能未被改动影响（`SKILL_CALL.md` 中写明验证结论）。
